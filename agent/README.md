# TallyPrime Private-LAN Sync Agent

The optional agent is a small Python relay for installations where Odoo cannot securely reach the
TallyPrime host. It calls Tally locally over HTTP/XML and makes outbound HTTPS requests to the Odoo
connector API. It contains no independent accounting transformation logic.

## Requirements

- Python 3.10 or newer.
- No third-party Python packages.
- Local/LAN access to TallyPrime's XML gateway.
- Outbound HTTPS access to Odoo.
- An agent token generated by one active Odoo Tally instance.

## Responsibilities

- Report heartbeat and open Tally companies.
- Pull leased outbound XML from Odoo and post it to Tally.
- Acknowledge accepted/failed queue work.
- Poll Tally master/voucher changes using Odoo-provided entity watermarks.
- Push raw XML/records to Odoo for centralized parsing, policy and upsert.

## Quick start

```bash
python3 tally_agent.py \
  --odoo-url "https://your-odoo.example.com" \
  --token "YOUR_INSTANCE_TOKEN" \
  --tally-host 127.0.0.1 \
  --tally-port 9000 \
  --interval 60
```

Equivalent environment variables:

- `ODOO_URL`
- `AGENT_TOKEN`
- `TALLY_HOST`
- `TALLY_PORT`
- `POLL_INTERVAL`

The current implementation accepts the token in an argument or environment variable. Use a
protected service configuration and limit file/process visibility. Never commit a token.

## Odoo preparation

1. Install `tally_integration`.
2. Create and configure the correct company instance.
3. Select agent connection mode.
4. Generate a token.
5. Load and review entity directions/source policies.
6. Keep the instance active and Odoo reachable through HTTPS.

## Tally preparation

1. Open TallyPrime and the intended company.
2. Enable the XML gateway, normally on port 9000.
3. Restrict the port to localhost or the trusted LAN host running the agent.
4. Confirm the agent host can export the open company.

## Windows service example

With Python and NSSM installed:

```powershell
nssm install OdooTallyAgent "C:\Python311\python.exe" "C:\OdooTally\agent\tally_agent.py"
nssm set OdooTallyAgent AppDirectory "C:\OdooTally"
nssm set OdooTallyAgent AppParameters --odoo-url https://your-odoo.example.com --token TOKEN --tally-host 127.0.0.1 --tally-port 9000 --interval 60
nssm start OdooTallyAgent
```

Prefer an approved Windows credential/secret mechanism instead of a visible token argument. Set the
service to restart on failure and after reboot, using a least-privilege account.

## Lease recovery

Odoo marks downloaded outbound items as `sent`. When an agent requests more work, leases older than
ten minutes are returned to `pending`. Stable GUID/idempotency behavior makes the resulting retry safe
within the connector contract.

## Troubleshooting

### Odoo returns unauthorized

- Confirm the token belongs to the intended active instance.
- Confirm no whitespace was copied.
- Confirm the database is the intended environment and clone guard is not blocking it.
- Regenerate the token after suspected exposure.

### Tally connection is refused

- Keep TallyPrime open.
- Enable Server/Both connectivity.
- Confirm the port and host firewall.
- Test from the same operating-system account as the service.

### Company is missing

- Open the target company in Tally.
- Confirm exact name in Odoo.
- Inspect discovered companies and agent logs.

### Queue remains sent

- Check agent process/network health.
- Wait for the ten-minute lease expiry or restart after correcting the fault.
- Do not directly edit queue rows in PostgreSQL.

## Security

- Use HTTPS to Odoo.
- Restrict local Tally gateway access.
- Protect and rotate the token.
- Do not log tokens or full sensitive accounting payloads externally.
- Run with a dedicated least-privilege OS account.
- Keep the host patched and monitor service health.
